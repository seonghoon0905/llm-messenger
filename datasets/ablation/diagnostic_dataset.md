# Ablation Evaluation 데이터셋

> **목적**: KOTE 감정 분석 모델과 3i4K 화행 분류 모델 각각의 고유 기여도를 측정하기 위한 진단 데이터셋
> **규모**: 100개 시나리오 (3가지 타입)
> **라벨 분포**: invoke (LLM 호출 필요) 50개 / skip (불필요) 50개
> **생성**: Claude Opus 4.7로 한국어 메신저 대화 양상에 맞춰 카테고리별 균형 있게 작성

---

## 데이터셋 구조

각 시나리오는 `(상대방 메시지, 내 답장 초안, 골드 라벨)` 의 3-tuple 이다.

| 타입 | 개수 | 설계 의도 | 골드 |
|---|---:|---|:---:|
| **A. 질문 (question)** | 25 | 상대방이 명확한 질문, 내 답장은 중립적 답변. 3i4K 화행 분류기가 `question` 으로 분류해야 catch | invoke |
| **B. 감정 (emotion)** | 25 | 상대방은 일상적 메시지, 내 답장이 강한 부정 감정을 담음. KOTE 감정 분석이 `neg_sum ≥ 0.4` 로 catch | invoke |
| **C. 무관 (skip)** | 50 | 상대방·답장 모두 평범한 인사·잡담. KOTE/3i4K 어느 쪽도 catch 하지 않아야 함 | skip |

### 평가 가설

| 모드 | 기대 정확도 | 근거 |
|---|---|---|
| `kote_pure` | 감정 catch O, 질문 catch X | KOTE는 감정 모델, 화행은 못 잡음 |
| `3i4k_pure` | 질문 catch O, 감정 catch X | 3i4K는 화행 모델, 감정은 못 잡음 |
| `both_pure` | **두 타입 모두 catch** | 상호 보완 |

## 데이터셋 검증

본 데이터셋의 골드 라벨링은 저자가 단독으로 수행하였으며, 평가자 간 일치도(inter-rater agreement)는 측정되지 않았다. 이는 본 평가의 한계이며, 향후 작업으로 **다수 평가자(annotator)를 통한 라벨 검증** 및 **실 사용자 채팅 로그 기반 재측정**이 필요하다.

## 사용

이 데이터셋은 `eval/pure_ablation_eval.py` 스크립트가 [`eval/datasets/diagnostic_scenarios.json`](./diagnostic_scenarios.json) 파일을 입력으로 받아 평가에 사용한다.

```bash
python3 -m eval.pure_ablation_eval --csv eval/out/pure_ablation.csv
```

평가 결과는 보고서 6절 (Ablation Study) 참고.
